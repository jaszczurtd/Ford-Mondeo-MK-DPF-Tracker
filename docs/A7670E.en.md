# A7670E -> Mosquitto connection test (TLS/8883): complete step-by-step procedure

## Environment

111.222.121.212 = replace with your external IP address<br>
192.168.2.100 = replace with your local IP address<br>
10.8.0.1 = replace with your WireGuard network address (optional)<br>

| Element | Value |
|---------|-------|
| MQTT broker | Raspberry Pi 5, Mosquitto on port 8883 (TLS) |
| Broker public IP | 111.222.121.212 |
| CA cert | Self-signed, PEM, 2195 bytes |
| Server cert SAN | IP:111.222.121.212, IP:192.168.2.100, IP:10.8.0.1, DNS:pi.local |
| Modem | Waveshare A7670E Cat-1 HAT, or KAmod LTE CAT1-GNSS - GSM/GPRS/GNSS HAT with the A7670E-FASE module, or anything based on A7670 |
| Operator | Your preferred one |
| Test computer | assume Linux Mint |

## PART 1: Preparing the RPi5 side (broker)

### 1.1 Copy the CA certificate to the test computer

From the computer:

```bash
scp pi@192.168.2.100:/etc/mosquitto/certs/ca.crt ~/ca.crt
```

(or from the public IP address if you are not on the local network)

Check the size - it must be exactly 2195 bytes:

```bash
wc -c ~/ca.crt
```

### 1.2 Start a test listener on the RPi5

On the RPi5, open a separate terminal and start the test subscription:

```bash
mosquitto_sub -h localhost -p 8883 \
  --cafile /etc/mosquitto/certs/ca.crt \
  -u YOUR_USER -P YOUR_PASSWORD \
  -t "dpf/test" -v
```

This terminal will wait for messages. When the modem sends a test
message, you will see it here.

### 1.3 Quick test from the computer (optional, but recommended)

First, make sure the broker accepts external connections at all.
From the computer:

```bash
mosquitto_pub -h 111.222.121.212 -p 8883 \
  --cafile ~/ca.crt \
  -u YOUR_USER -P YOUR_PASSWORD \
  -t "dpf/test" -m "hello from linux mint"
```

If the message appears in the mosquitto_sub terminal on the RPi5,
the broker works, the certificate is OK, and the port is open.

If it does NOT work, check the firewall on the RPi5 and routing.

## PART 2: Connecting the A7670E modem to the computer

### 2.1 Physical connection

1. Insert the SIM card into the slot on the A7670E module
2. Connect the LTE antenna
3. Connect a USB Type-C cable from the modem to the computer
4. Wait 3-5 seconds for the modem to start (the PWR LED will light up)
5. The NET LED will start blinking when the modem registers on the network

### 2.2 Check the serial port

```bash
ls /dev/ttyUSB*
```

You should see ports such as `/dev/ttyUSB0`, `/dev/ttyUSB1`, etc.
For AT commands, `/dev/ttyUSB2` is usually used (AT port), but this may
vary - check it with:

```bash
dmesg | grep ttyUSB | tail -10
```

Mini script for detecting the modem:

```bash
for p in /dev/ttyUSB{1..4}; do
    echo "=== $p ==="
    udevadm info -q property -n "$p" |
        grep -E '^(ID_USB_INTERFACE_NUM|ID_MM_PORT_TYPE_AT_PRIMARY)='
done
```

The detected modem will be on the serial port that reports ID_USB_INTERFACE_NUM=04 or ID_MM_PORT_TYPE_AT_PRIMARY=1.

### 2.3 Open a serial terminal

```bash
sudo apt install minicom          # if you do not have it
minicom -D /dev/ttyUSB2 -b 115200 # assuming the modem was detected as /dev/ttyUSB2
```

> NOTE: In minicom, disable hardware flow control:
> Ctrl+A -> O -> Serial port setup -> F (Hardware Flow Control: No)
> Otherwise, AT commands may not go through.

Alternatively, use picocom (simpler, and recommended by me):

```bash
sudo apt install picocom
picocom -b 115200 /dev/ttyUSB2
```

> Press Ctrl+A, release it, then press Ctrl+C. This enables local echo - you should see a message with local echo: yes.
> This will allow you to see the text you type in the console.

## PART 3: AT commands - step by step

Enter each command manually, wait for the response, and only then
enter the next one. Modem responses are marked as `<- `

### 3.1 Basic verification

```
AT
```
<- `OK`

Check whether the modem is alive.

```
ATI
```
<- Module info (it should show A7670E)

```
AT+CPIN?
```
<- `+CPIN: READY`

If `SIM PIN` appears, you must enter the PIN: `AT+CPIN="1234"`
If `SIM not inserted` appears, check the SIM card.

Diagnostic command sequence:

```
AT
ATE1
AT+CMEE=2
ATI
AT+CGMR
AT+CPIN?
AT+CFUN?
AT+CSQ
AT+CPSI?
AT+CEREG?
AT+CREG?
AT+CGREG?
AT+COPS?
AT+CNMP?
AT+CNBP?
AT+CGATT?
AT+CEER
```

Most important responses:

| Command | Interpretation |
|---------|----------------|
| AT+CPIN? READY | card ready; SIM PIN / SIM PUK = requires unlocking. |
| AT+CFUN? | 1 = normal operation; 0 = minimum functionality; 4 = radio disabled. |
| AT+CSQ | First value: 0-31 is the signal level; 99 means no available measurement. |
| AT+CPSI? | Technology, cell, and radio parameters, or information about no service. |

For LTE registration, AT+CEREG? is key, not just AT+CREG?. The response has the form +CEREG: <n>,<stat>,... - the status is the second number: <stat>
<br><br>
| Value | Meaning |
|-------|---------|
| 0 | Not registered, currently not searching. |
| 1 | Registered on the home network. |
| 2 | Searching for a network / trying to register. |
| 3 | Registration rejected. |
| 4 | Unknown state. |
| 5 | Registered while roaming. |

For example, +CEREG: 0,1 means successful registration, not an error.

In case of rejection, it is worth saving AT+CEER, but the report may refer to an earlier event. Only after saving the readings can you run an operator scan:

```
AT+COPS=?
```

### 3.2 Network registration

```
AT+CSQ
```
<- `+CSQ: XX,YY`

XX = signal strength (10-31 is OK, >15 is good)
If XX = 99 -> no signal, check the antenna.

```
AT+CREG?
```
<- `+CREG: 0,1` (1 = registered on home network)
or `+CREG: 0,5` (5 = registered, roaming)

If 0,2 -> searching for network, wait.
If 0,3 -> registration denied, SIM/operator problem.

```
AT+CGREG?
```
<- `+CGREG: 0,1` (packet data registration)

```
AT+COPS?
```
<- `+COPS: 0,0,"Orange PL",7`

Confirms the operator. The digit 7 at the end = LTE.

### 3.3 APN configuration (Orange PL)

```
AT+CGDCONT=1,"IP","internet"
```
<- `OK`

The APN for Orange PL is "internet".

Activate the PDP context:

```
AT+CGACT=1,1
```
<- `OK`

Check the assigned IP address:

```
AT+CGPADDR=1
```
<- `+CGPADDR: 1,"xx.xx.xx.xx"` (IP from the Orange network)

### 3.4 Connectivity test (optional)

```
AT+CPING="111.222.121.212",1,4,64,1000,10000,255
```
<- You should see ping responses to your RPi5.

If it times out, check the firewall on the RPi5 (ICMP).
Even if ping does not work, TCP/MQTT may still work.

## PART 4: Uploading the CA certificate to the modem

### 4.1 List current certificates

```
AT+CCERTLIST
```
<- List (may be empty)

### 4.2 Upload the CA certificate

Size of the ca.crt file = 2195 bytes.

```
AT+CCERTDOWN="ca.pem",2195
```
<- `>` (the modem is waiting for data)

Now you must send EXACTLY 2195 bytes of the ca.crt file contents.

**Method 1 - from picocom:**
In a separate terminal:

```bash
# Send the file directly to the serial port
cat ~/ca.crt > /dev/ttyUSB2
```

**Method 2 - from minicom:**
Ctrl+A -> Y -> select the ~/ca.crt file (ASCII upload)

**Method 3 - Python script (most reliable):**

```python
#!/usr/bin/env python3
"""Upload the CA certificate to the A7670E modem"""

import serial
import time

PORT = "/dev/ttyUSB2"   # adjust to your port
BAUD = 115200
CERT_FILE = "/home/YOUR_USER/ca.crt"  # path to the certificate

def send_at(ser, cmd, wait=2):
    """Send an AT command and print the response."""
    ser.write((cmd + "\r\n").encode())
    time.sleep(wait)
    resp = ser.read(ser.in_waiting).decode(errors='ignore')
    print(f">>> {cmd}")
    print(f"<<< {resp}")
    return resp

def main():
    # Read the certificate
    with open(CERT_FILE, "rb") as f:
        cert_data = f.read()
    cert_size = len(cert_data)
    print(f"Certificate size: {cert_size} bytes")

    ser = serial.Serial(PORT, BAUD, timeout=5)
    time.sleep(1)

    # Connection test
    send_at(ser, "AT")

    # List existing certificates
    send_at(ser, "AT+CCERTLIST")

    # Start upload
    cmd = f'AT+CCERTDOWN="ca.pem",{cert_size}'
    ser.write((cmd + "\r\n").encode())
    time.sleep(1)
    resp = ser.read(ser.in_waiting).decode(errors='ignore')
    print(f">>> {cmd}")
    print(f"<<< {resp}")

    if ">" in resp:
        # Modem is waiting for data - send the certificate
        ser.write(cert_data)
        time.sleep(3)
        resp = ser.read(ser.in_waiting).decode(errors='ignore')
        print(f"<<< {resp}")
        if "OK" in resp:
            print("✓ Certificate uploaded successfully!")
        else:
            print("✗ Certificate upload error!")
    else:
        print("✗ Modem did not respond with the '>' prompt")

    # Verification
    send_at(ser, "AT+CCERTLIST")

    ser.close()

if __name__ == "__main__":
    main()
```

Run:

```bash
pip install pyserial
python3 upload_cert.py
```

### 4.3 Verification

```
AT+CCERTLIST
```
<- `+CCERTLIST: "ca.pem"` (the certificate is in the module)

## PART 5: SSL configuration and MQTT connection

### 5.1 SSL context configuration

```
AT+CSSLCFG="sslversion",0,4
```
<- `OK`

(4 = all; the modem will negotiate the highest supported TLS version)

```
AT+CSSLCFG="authmode",0,1
```
<- `OK`

(1 = server verification using the CA certificate)

```
AT+CSSLCFG="cacert",0,"ca.pem"
```
<- `OK`

(points to the CA certificate uploaded in step 4.2)

```
AT+CSSLCFG="ignorelocaltime",0,1
```
<- `OK`

(ignores local time mismatch - useful because the modem
may not have its clock synchronized with NTP)

### 5.2 Start the MQTT client

```
AT+CMQTTSTART
```
<- `+CMQTTSTART: 0` (0 = success)

### 5.3 Create an MQTT client with SSL

```
AT+CMQTTACCQ=0,"dpf-tracker-test",1
```
<- `OK`

Parameters:
- 0 = client index
- "dpf-tracker-test" = Client ID
- 1 = server type (1 = SSL/TLS)

### 5.4 Bind the SSL context to the MQTT client

```
AT+CMQTTSSLCFG=0,0
```
<- `OK`

(MQTT client 0 uses SSL context 0)

### 5.5 Connect to the broker

```
AT+CMQTTCONNECT=0,"tcp://111.222.121.212:8883",60,1,"YOUR_USER","YOUR_PASSWORD"
```
<- `OK`
<- `+CMQTTCONNECT: 0,0`

Second response parameter:
- 0 = success
- 1 = connection refused (bad protocol)
- 2 = connection refused (bad client ID)
- 4 = connection refused (bad user/password)
- 5 = connection refused (no authorization)

> IMPORTANT: Even though this is TLS, the prefix is still "tcp://" in
> SIMCom commands. SSL is configured separately through CSSLCFG, not by
> changing the URL prefix.

If you get `+CMQTTCONNECT: 0,0` - **connection established!**

## PART 6: Publishing a test message

### 6.1 Set the topic

```
AT+CMQTTTOPIC=0,8
```
<- `>`

Enter the topic (exactly 8 characters):

```
dpf/test
```
<- `OK`

### 6.2 Set the message payload

```
AT+CMQTTPAYLOAD=0,24
```
<- `>`

Enter the payload (exactly 24 characters):

```
hello from A7670E modem!
```
<- `OK`

### 6.3 Publish

```
AT+CMQTTPUB=0,1,60
```
<- `OK`
<- `+CMQTTPUB: 0,0` (0 = success)

Parameters:
- 0 = client index
- 1 = QoS (1 = at least once)
- 60 = timeout in seconds

**Check the RPi5 terminal** - the following should appear in mosquitto_sub:

```
dpf/test hello from A7670E modem!
```

## Troubleshooting

### The modem does not register on the network
- Check the LTE antenna (it must be screwed in!)
- `AT+CFUN=1,1` - restart the modem
- `AT+COPS=0` - automatic network selection

### CMQTTCONNECT returns an error
- Code 4 -> wrong user/password - check the credentials
- Code 6 -> TLS problem - try authmode=0:
  `AT+CSSLCFG="authmode",0,0`
  and repeat from CMQTTSTART
- Timeout -> check whether port 8883 is open on the RPi5:
  `sudo ss -tlnp | grep 8883`
- Check the firewall:
  `sudo iptables -L -n | grep 8883`

### The certificate does not work (SSL handshake error)
Plan B - test without certificate verification:

```
AT+CSSLCFG="authmode",0,0
```

If it works with authmode=0, but not with authmode=1, the problem is
certificate verification (the modem probably does not support IP addresses
in SAN). In that case:
- Generate a new certificate with a domain in SAN
- Or stay on authmode=0 + user/password (acceptable
  security for this application)

### I do not see any /dev/ttyUSB* ports
- `sudo apt install usb-modeswitch`
- `lsusb` - check whether the modem is visible
- Try a different USB cable
