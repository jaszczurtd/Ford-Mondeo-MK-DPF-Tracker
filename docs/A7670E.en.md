# Manual A7670E MQTT/TLS test

[Polski](A7670E.pl.md) · [Project overview](../README.md)

Use this procedure to isolate modem, SIM, broker and certificate problems
before running the tracker. It assumes a SIMCom A7670E board with USB AT access,
a Linux computer, and an existing Mosquitto TLS listener on port 8883.
Prepare the board's power supply, LTE antenna and SIM according to its hardware
instructions. Close the tracker connection while using the same modem manually.

Commands below use documentation address `203.0.113.10`; replace it with your
broker address and replace `YOUR_USER`/`YOUR_PASSWORD`. The broker address used
by each client must match the server certificate. Use your operator's APN;
`internet` is the tracker default, not a universal setting.

## Check the broker first

Copy the broker's CA certificate to the computer, for example:

```bash
scp pi@192.168.2.100:/etc/mosquitto/certs/ca.crt ~/ca.crt
wc -c ~/ca.crt
```

Replace the LAN address too. The size depends on your certificate; it is not
fixed at 2195 bytes. Subscribe from the computer using an address covered by
the certificate:

```bash
mosquitto_sub -h 203.0.113.10 -p 8883 --cafile ~/ca.crt \
  -u YOUR_USER -P YOUR_PASSWORD -t dpf/test -v
```

In another terminal, publish:

```bash
mosquitto_pub -h 203.0.113.10 -p 8883 --cafile ~/ca.crt \
  -u YOUR_USER -P YOUR_PASSWORD -t dpf/test -m 'hello from linux'
```

The subscriber should print the message. If it does not, resolve broker,
certificate, routing or firewall errors before proceeding. `localhost` works
only if the certificate covers that name, even when testing on the broker host.

## Find the AT port

Connect the modem USB interface and inspect the ports:

```bash
ls /dev/ttyUSB*
dmesg | grep ttyUSB | tail -10
```

`/dev/ttyUSB2` is an example, not a guaranteed assignment. USB interface
properties can help identify the port, but confirm it by receiving `OK` for
`AT`. Open only one serial application at a time. With picocom installed:

```bash
picocom --flow n -b 115200 /dev/ttyUSB2
```

Alternatively use `minicom -D /dev/ttyUSB2 -b 115200` with hardware and software
flow control disabled. Send each AT command separately and wait for its result.
For commands with an asynchronous result, `OK` alone is not completion.

## SIM, network and PDP

Collect the basic state:

```text
AT
ATE1
AT+CMEE=2
ATI
AT+CGMR
AT+CPIN?
AT+CFUN?
AT+CSQ
AT+CPSI?
AT+CEREG?
AT+CREG?
AT+CGREG?
AT+COPS?
AT+CNMP?
AT+CNBP?
AT+CGATT?
AT+CEER
```

`CPIN: READY` means the SIM is ready. If it asks for a PIN, send your actual
PIN with `AT+CPIN="1234"` after replacing the example. Stop after rejection
and resolve the PIN/PUK state; each wrong attempt uses the SIM's retry budget.

For LTE use `CEREG`: in `+CEREG: <n>,<stat>`, the second value is the status.
`1` means home registration, `5` roaming, `2` searching and `3` rejection.
`CSQ` with signal value `99` means unavailable. Preserve `CEER` diagnostics
before trying automatic operator selection (`AT+COPS=0`) or an operator scan
(`AT+COPS=?`), which may take a long time.

Set your APN, activate PDP and inspect the assigned address:

```text
AT+CGDCONT=1,"IP","internet"
AT+CGACT=1,1
AT+CGPADDR=1
```

An optional `AT+CPING="203.0.113.10",1,4,64,1000,10000,255` checks ICMP access.
A failed ping does not by itself establish that TCP port 8883 is unreachable.

## Install the CA certificate

The tracker expects a certificate named `ca.pem` already in modem storage;
it does not upload `CR_CA_CERT` from Credentials. Close the serial terminal
before running the uploader example below. Save it as `/tmp/upload_cert.py`, with the verified port and certificate path.

The example calculates the byte count, waits for the data prompt, sends the
file unchanged and waits for the final result. Avoid terminal ASCII-upload
modes that add line endings or translate bytes.

```python
from pathlib import Path
import time
import serial

port = "/dev/ttyUSB2"  # Select the verified AT port.
certificate = Path.home().joinpath("ca.crt").read_bytes()

def wait_for(ser, marker, timeout):
    deadline = time.monotonic() + timeout
    response = bytearray()
    while time.monotonic() < deadline:
        response.extend(ser.read(ser.in_waiting or 1))
        if b"ERROR" in response:
            raise RuntimeError(bytes(response))
        if marker in response:
            return bytes(response)
    raise TimeoutError(bytes(response))

with serial.Serial(port, 115200, timeout=0.2, write_timeout=10,
                   rtscts=False, xonxoff=False) as ser:
    ser.write(b"AT\r\n")
    wait_for(ser, b"\r\nOK\r\n", 5)
    command = f'AT+CCERTDOWN="ca.pem",{len(certificate)}\r\n'
    ser.write(command.encode("ascii"))
    wait_for(ser, b">", 10)
    if ser.write(certificate) != len(certificate):
        raise RuntimeError("Incomplete certificate write")
    ser.flush()
    wait_for(ser, b"\r\nOK\r\n", 30)
    ser.write(b"AT+CCERTLIST\r\n")
    print(wait_for(ser, b"\r\nOK\r\n", 5).decode(errors="replace"))
```

Run it in a virtual environment with pyserial:

```bash
python3 -m venv /tmp/a7670-at-venv
/tmp/a7670-at-venv/bin/pip install pyserial
/tmp/a7670-at-venv/bin/python /tmp/upload_cert.py
```

The listing must contain `ca.pem`. Reopen the serial terminal and use
`AT+CCERTLIST` to inspect stored certificates when diagnosing a later failure.

## Connect MQTT over TLS

The following sequence mirrors the current tracker configuration. Send each
line after the preceding command completes:

```text
AT+CSSLCFG="sslversion",0,4
AT+CSSLCFG="authmode",0,1
AT+CSSLCFG="cacert",0,"ca.pem"
AT+CSSLCFG="ignorelocaltime",0,1
AT+CSSLCFG="enableSNI",0,0
AT+CMQTTSTART
AT+CMQTTACCQ=0,"dpf-tracker-test",1
AT+CMQTTSSLCFG=0,0
AT+CMQTTCONNECT=0,"tcp://203.0.113.10:8883",60,1,"YOUR_USER","YOUR_PASSWORD"
```

Wait for `+CMQTTSTART: 0` and then `+CMQTTCONNECT: 0,0`. The test uses its
own client ID and a 60-second keepalive; firmware uses `dpf-tracker` and 120.
The `tcp://` prefix remains even with TLS, selected by the client/context setup.

In the [SIMCom manual, §19.2.1](https://files.waveshare.com/wiki/A7670E-Cat-1-GNSS-HAT/A76XX_Series_AT_Command_Manual_V1.09.pdf#page=424), `sslversion=4` permits all
supported versions; `3` selects TLS 1.2. The existing code comments calling
`4` TLS 1.2 do not match that table. `authmode=1` verifies the server certificate;
`ignorelocaltime=1` skips its time-validity check. SNI is disabled here, as in
firmware. A server requiring SNI needs a matching configuration change.

## Publish and disconnect

After each `>` prompt, send exactly the stated number of bytes, without an
extra CR/LF. These examples use ASCII; for other text count encoded bytes.

```text
AT+CMQTTTOPIC=0,8
```

Send `dpf/test` (8 bytes), then wait for `OK`.

```text
AT+CMQTTPAYLOAD=0,24
```

Send `hello from A7670E modem!` (24 bytes), then wait for `OK`.

```text
AT+CMQTTPUB=0,1,60
```

Wait for `+CMQTTPUB: 0,0` and verify the subscriber receives
`dpf/test hello from A7670E modem!`. Close the session, waiting for each result:

```text
AT+CMQTTDISC=0,60
AT+CMQTTREL=0
AT+CMQTTSTOP
```

## Diagnose failures

Read `+CMQTTCONNECT: <client>,<err>` using SIMCom's result table, not MQTT
CONNACK numbering. Selected values from
[§18.3](https://files.waveshare.com/wiki/A7670E-Cat-1-GNSS-HAT/A76XX_Series_AT_Command_Manual_V1.09.pdf#page=417):

| Code | Meaning |
| --- | --- |
| 3 / 4 / 6 | Socket connection / creation / message receive failure |
| 17 / 25 | Timeout / DNS failure |
| 27 / 28 / 29 | Rejected protocol / client ID / unavailable server |
| 30 / 31 | Bad credentials / not authorized |
| 32 / 33 | Handshake failure / certificate not set |

For registration failures, check SIM state, LTE antenna, operator and `CEREG`.
For connection failures, check PDP address, routing, listener port and broker
logs. For certificate failures, check the uploaded file, CA chain, certificate
name/address and firmware-specific TLS settings. Disabling `authmode` removes
server authentication; do not treat that as a successful verified TLS test.
A verification failure alone does not prove that IP SAN is unsupported.

If no USB ports appear, inspect `lsusb`, the USB cable, board power and USB mode.
Save the modem revision (`CGMR`) with diagnostics and consult the manual for
that revision. This procedure tests a real modem and broker; syntax checks
or firmware builds do not establish its hardware result.
