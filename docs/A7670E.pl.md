# Test połączenia A7670E -> Mosquitto (TLS/8883) : Kompletna procedura krok po kroku

## Środowisko

111.222.121.212 = zmień na Twój zewnętrzny IP<br>
192.168.2.100 = zmień na Twój lokalny adres IP<br>
10.8.0.1 = zmień na Twój adres sieci wireguard (opcjonalnie)<br>

| Element | Wartość |
|---------|---------|
| Broker MQTT | Raspberry Pi 5, Mosquitto na porcie 8883 (TLS) |
| IP publiczne brokera | 111.222.121.212 |
| CA cert | Self-signed, PEM, 2195 bajtów |
| Server cert SAN | IP:111.222.121.212, IP:192.168.2.100, IP:10.8.0.1, DNS:pi.local |
| Modem | Waveshare A7670E Cat-1 HAT, lub KAmod LTE CAT1-GNSS - HAT GSM/GPRS/GNSS z modułem A7670E-FASE, lub cokolwiek z A7670 |
| Operator | Twój ulubiony |
| Komputer testowy | załóżmy że Linux Mint |

## CZĘŚĆ 1: Przygotowanie po stronie RPi5 (brokera)

### 1.1 Skopiuj certyfikat CA na komputer testowy

Z komputera:

```bash
scp pi@192.168.2.100:/etc/mosquitto/certs/ca.crt ~/ca.crt
```

(lub z publicznego IP jeśli nie jesteś w sieci lokalnej)

Sprawdź rozmiar - musi być dokładnie 2195 bajtów:

```bash
wc -c ~/ca.crt
```

### 1.2 Uruchom nasłuch testowy na RPi5

Na RPi5 otwórz osobny terminal i uruchom subskrypcję testową:

```bash
mosquitto_sub -h localhost -p 8883 \
  --cafile /etc/mosquitto/certs/ca.crt \
  -u TWOJ_USER -P TWOJE_HASLO \
  -t "dpf/test" -v
```

Ten terminal będzie czekał na wiadomości. Jak modem wyśle testową
wiadomość - zobaczysz ją tutaj.

### 1.3 Szybki test z komputera (opcjonalny, ale zalecany)

Najpierw upewnij się, że broker w ogóle przyjmuje połączenia z zewnątrz.
Z komputera:

```bash
mosquitto_pub -h 111.222.121.212 -p 8883 \
  --cafile ~/ca.crt \
  -u TWOJ_USER -P TWOJE_HASLO \
  -t "dpf/test" -m "hello from linux mint"
```

Jeśli na RPi5 w terminalu z mosquitto_sub pojawi się wiadomość -
broker działa, certyfikat jest OK, port jest otwarty.

Jeśli NIE działa - sprawdź firewall na RPi5 i routing.

## CZĘŚĆ 2: Podłączenie modemu A7670E do komputera

### 2.1 Fizyczne podłączenie

1. Włóż kartę SIM do slotu w module A7670E
2. Podłącz antenę LTE
3. Podłącz kabel USB Type-C z modemu do komputera
4. Odczekaj 3-5 sekund na start modemu (LED PWR zaświeci się)
5. LED NET zacznie migać gdy modem zarejestruje się w sieci

### 2.2 Sprawdź port szeregowy

```bash
ls /dev/ttyUSB*
```

Powinny pojawić się porty, np. `/dev/ttyUSB0`, `/dev/ttyUSB1`, itd.
Do komend AT zazwyczaj używamy `/dev/ttyUSB2` (AT port), ale może
się różnić - sprawdź:

```bash
dmesg | grep ttyUSB | tail -10
```

Mini skrypt do wykrycia modemu:

```bash
for p in /dev/ttyUSB{1..4}; do
    echo "=== $p ==="
    udevadm info -q property -n "$p" |
        grep -E '^(ID_USB_INTERFACE_NUM|ID_MM_PORT_TYPE_AT_PRIMARY)='
done
```

Wykryty modem będzie pod portem szeregowym który zgłosi ID_USB_INTERFACE_NUM=04 albo ID_MM_PORT_TYPE_AT_PRIMARY=1.

### 2.3 Otwórz terminal szeregowy

```bash
sudo apt install minicom          # jeśli nie masz
minicom -D /dev/ttyUSB2 -b 115200 # przy założeniu że modem został wykryty pod /dev/ttyUSB2
```

> UWAGA: W minicom wyłącz hardware flow control:
> Ctrl+A -> O -> Serial port setup -> F (Hardware Flow Control: No)
> Inaczej komendy AT mogą nie przechodzić.

Alternatywnie picocom (prostszy, i przeze mnie polecany):

```bash
sudo apt install picocom
picocom -b 115200 /dev/ttyUSB2
```

> Naciśnij Ctrl+A, puść, następnie Ctrl+C. To włącza lokalne echo - powinien pojawić się komunikat z local echo: yes.
> To pozwoli Ci na zobaczenie tekstu który wpisujesz w konsoli.

## CZĘŚĆ 3: Komendy AT - krok po kroku

Każdą komendę wpisuj ręcznie, czekaj na odpowiedź, i dopiero
wtedy wpisuj następną. Odpowiedzi modemu oznaczam jako `<- `

### 3.1 Weryfikacja podstawowa

```
AT
```
<- `OK`

Sprawdź czy modem żyje.

```
ATI
```
<- Info o module (powinien pokazać A7670E)

```
AT+CPIN?
```
<- `+CPIN: READY`

Jeśli `SIM PIN` - musisz podać PIN: `AT+CPIN="1234"`
Jeśli `SIM not inserted` - sprawdź kartę SIM.

Seria komend diagnostycznych:

```
AT
ATE1
AT+CMEE=2
ATI
AT+CGMR
AT+CPIN?
AT+CFUN?
AT+CSQ
AT+CPSI?
AT+CEREG?
AT+CREG?
AT+CGREG?
AT+COPS?
AT+CNMP?
AT+CNBP?
AT+CGATT?
AT+CEER
```

Najważniejsze odpowiedzi:

| Polecenie | Interpretacja |
|-----------|---------------|
| AT+CPIN?	READY  |  karta gotowa; SIM PIN / SIM PUK = wymaga odblokowania. |
| AT+CFUN?	 | 1 = normalna praca; 0 = minimum funkcji; 4 = radio wyłączone. |
| AT+CSQ	 | Pierwsza wartość: 0–31 to poziom sygnału; 99 oznacza brak dostępnego pomiaru. |
| AT+CPSI?	 | Technologia, komórka i parametry radiowe albo informacja o braku usługi. |

Dla rejestracji w LTE kluczowe jest AT+CEREG?, nie samo AT+CREG?. Odpowiedź ma postać +CEREG: <n>,<stat>,... - status to druga liczba: <stat>	
<br><br>
| Wartość | Znaczenie    |
|---------|--------------|
| 0	| Niezarejestrowany, obecnie nie szuka. |
| 1	| Zarejestrowany w sieci macierzystej. |
| 2	| Szuka sieci / próbuje się zarejestrować. |
| 3	| Rejestracja odrzucona. |
| 4	| Stan nieznany. |
| 5	| Zarejestrowany w roamingu. |

Przykładowo +CEREG: 0,1 oznacza udaną rejestrację, nie błąd.

Przy odrzuceniu warto zachować AT+CEER, ale raport może dotyczyć wcześniejszego zdarzenia. Dopiero po zapisaniu odczytów można zrobić skan operatorów:

```
AT+COPS=?
```

### 3.2 Rejestracja w sieci

```
AT+CSQ
```
<- `+CSQ: XX,YY`

XX = siła sygnału (10-31 to OK, >15 dobrze)
Jeśli XX = 99 -> brak sygnału, sprawdź antenę.

```
AT+CREG?
```
<- `+CREG: 0,1` (1 = zarejestrowany w sieci domowej)
lub `+CREG: 0,5` (5 = zarejestrowany, roaming)

Jeśli 0,2 -> szuka sieci, poczekaj.
Jeśli 0,3 -> odmowa rejestracji, problem z SIM/operatorem.

```
AT+CGREG?
```
<- `+CGREG: 0,1` (rejestracja danych pakietowych)

```
AT+COPS?
```
<- `+COPS: 0,0,"Orange PL",7`

Potwierdza operatora. Cyfra 7 na końcu = LTE.

### 3.3 Konfiguracja APN (Orange PL)

```
AT+CGDCONT=1,"IP","internet"
```
<- `OK`

APN dla Orange PL to "internet".

Aktywuj kontekst PDP:

```
AT+CGACT=1,1
```
<- `OK`

Sprawdź przydzielony IP:

```
AT+CGPADDR=1
```
<- `+CGPADDR: 1,"xx.xx.xx.xx"` (IP z sieci Orange)

### 3.4 Test łączności (opcjonalny)

```
AT+CPING="111.222.121.212",1,4,64,1000,10000,255
```
<- Powinny pojawić się odpowiedzi ping do Twojego RPi5.

Jeśli timeout - sprawdź firewall na RPi5 (ICMP).
Nawet jeśli ping nie przechodzi, TCP/MQTT może działać.

## CZĘŚĆ 4: Wgranie certyfikatu CA do modemu

### 4.1 Wylistuj obecne certyfikaty

```
AT+CCERTLIST
```
<- Lista (może być pusta)

### 4.2 Wgraj certyfikat CA

Rozmiar pliku ca.crt = 2195 bajtów.

```
AT+CCERTDOWN="ca.pem",2195
```
<- `>` (modem czeka na dane)

Teraz musisz wysłać DOKŁADNIE 2195 bajtów zawartości pliku ca.crt.

**Sposób 1 - z poziomu picocom:**
W osobnym terminalu:

```bash
# Wyślij plik bezpośrednio na port szeregowy
cat ~/ca.crt > /dev/ttyUSB2
```

**Sposób 2 - z poziomu minicom:**
Ctrl+A -> Y -> wybierz plik ~/ca.crt (upload ASCII)

**Sposób 3 - skrypt Python (najbardziej niezawodny):**

```python
#!/usr/bin/env python3
"""Wgrywanie certyfikatu CA do modemu A7670E"""

import serial
import time

PORT = "/dev/ttyUSB2"   # dostosuj do swojego portu
BAUD = 115200
CERT_FILE = "/home/TWOJ_USER/ca.crt"  # ścieżka do certyfikatu

def send_at(ser, cmd, wait=2):
    """Wyślij komendę AT i wypisz odpowiedź."""
    ser.write((cmd + "\r\n").encode())
    time.sleep(wait)
    resp = ser.read(ser.in_waiting).decode(errors='ignore')
    print(f">>> {cmd}")
    print(f"<<< {resp}")
    return resp

def main():
    # Odczytaj certyfikat
    with open(CERT_FILE, "rb") as f:
        cert_data = f.read()
    cert_size = len(cert_data)
    print(f"Rozmiar certyfikatu: {cert_size} bajtów")

    ser = serial.Serial(PORT, BAUD, timeout=5)
    time.sleep(1)

    # Test połączenia
    send_at(ser, "AT")

    # Wylistuj istniejące certyfikaty
    send_at(ser, "AT+CCERTLIST")

    # Rozpocznij upload
    cmd = f'AT+CCERTDOWN="ca.pem",{cert_size}'
    ser.write((cmd + "\r\n").encode())
    time.sleep(1)
    resp = ser.read(ser.in_waiting).decode(errors='ignore')
    print(f">>> {cmd}")
    print(f"<<< {resp}")

    if ">" in resp:
        # Modem czeka na dane - wyślij certyfikat
        ser.write(cert_data)
        time.sleep(3)
        resp = ser.read(ser.in_waiting).decode(errors='ignore')
        print(f"<<< {resp}")
        if "OK" in resp:
            print("✓ Certyfikat wgrany pomyślnie!")
        else:
            print("✗ Błąd wgrywania certyfikatu!")
    else:
        print("✗ Modem nie odpowiedział promptem '>'")

    # Weryfikacja
    send_at(ser, "AT+CCERTLIST")

    ser.close()

if __name__ == "__main__":
    main()
```

Uruchom:

```bash
pip install pyserial
python3 upload_cert.py
```

### 4.3 Weryfikacja

```
AT+CCERTLIST
```
<- `+CCERTLIST: "ca.pem"` (certyfikat jest w module)

## CZĘŚĆ 5: Konfiguracja SSL i połączenie MQTT

### 5.1 Konfiguracja kontekstu SSL

```
AT+CSSLCFG="sslversion",0,4
```
<- `OK`

(4 = all, modem wynegocjuje najwyższą obsługiwaną wersję TLS)

```
AT+CSSLCFG="authmode",0,1
```
<- `OK`

(1 = weryfikacja serwera certyfikatem CA)

```
AT+CSSLCFG="cacert",0,"ca.pem"
```
<- `OK`

(wskazuje certyfikat CA wgrany w kroku 4.2)

```
AT+CSSLCFG="ignorelocaltime",0,1
```
<- `OK`

(ignoruje rozbieżność czasu lokalnego - przydatne, bo modem
może nie mieć zsynchronizowanego zegara z NTP)

### 5.2 Uruchomienie klienta MQTT

```
AT+CMQTTSTART
```
<- `+CMQTTSTART: 0` (0 = sukces)

### 5.3 Utworzenie klienta MQTT z SSL

```
AT+CMQTTACCQ=0,"dpf-tracker-test",1
```
<- `OK`

Parametry:
- 0 = indeks klienta
- "dpf-tracker-test" = Client ID
- 1 = typ serwera (1 = SSL/TLS)

### 5.4 Powiązanie kontekstu SSL z klientem MQTT

```
AT+CMQTTSSLCFG=0,0
```
<- `OK`

(klient MQTT 0 używa kontekstu SSL 0)

### 5.5 Połączenie z brokerem

```
AT+CMQTTCONNECT=0,"tcp://111.222.121.212:8883",60,1,"TWOJ_USER","TWOJE_HASLO"
```
<- `OK`
<- `+CMQTTCONNECT: 0,0`

Drugi parametr odpowiedzi:
- 0 = sukces
- 1 = connection refused (zły protokół)
- 2 = connection refused (zły client ID)
- 4 = connection refused (zły user/password)
- 5 = connection refused (brak autoryzacji)

> WAŻNE: Mimo że to TLS, prefiks to nadal "tcp://" w komendach
> SIMCom. SSL jest konfigurowany osobno przez CSSLCFG, nie przez
> zmianę prefiksu URL.

Jeśli `+CMQTTCONNECT: 0,0` - **połączenie nawiązane!**

## CZĘŚĆ 6: Publikacja testowej wiadomości

### 6.1 Ustaw temat (topic)

```
AT+CMQTTTOPIC=0,8
```
<- `>`

Wpisz temat (dokładnie 8 znaków):

```
dpf/test
```
<- `OK`

### 6.2 Ustaw treść wiadomości (payload)

```
AT+CMQTTPAYLOAD=0,24
```
<- `>`

Wpisz treść (dokładnie 24 znaki):

```
hello from A7670E modem!
```
<- `OK`

### 6.3 Opublikuj

```
AT+CMQTTPUB=0,1,60
```
<- `OK`
<- `+CMQTTPUB: 0,0` (0 = sukces)

Parametry:
- 0 = indeks klienta
- 1 = QoS (1 = at least once)
- 60 = timeout w sekundach

**Sprawdź terminal RPi5** - w mosquitto_sub powinno pojawić się:

```
dpf/test hello from A7670E modem!
```

## Rozwiązywanie problemów

### Modem nie rejestruje się w sieci
- Sprawdź antenę LTE (musi być przykręcona!)
- `AT+CFUN=1,1` - restart modemu
- `AT+COPS=0` - automatyczny wybór sieci

### CMQTTCONNECT zwraca błąd
- Kod 4 -> zły user/password - sprawdź dane logowania
- Kod 6 -> problem z TLS - spróbuj authmode=0:
  `AT+CSSLCFG="authmode",0,0`
  i powtórz od CMQTTSTART
- Timeout -> sprawdź czy port 8883 jest otwarty na RPi5:
  `sudo ss -tlnp | grep 8883`
- Sprawdź firewall:
  `sudo iptables -L -n | grep 8883`

### Certyfikat nie działa (błąd SSL handshake)
Plan B - testuj bez weryfikacji certyfikatu:

```
AT+CSSLCFG="authmode",0,0
```

Jeśli z authmode=0 działa, a z authmode=1 nie - problem jest
w weryfikacji certyfikatu (prawdopodobnie modem nie obsługuje
IP w SAN). W takim przypadku:
- Wygeneruj nowy certyfikat z domeną w SAN
- Lub zostań na authmode=0 + user/password (akceptowalne
  bezpieczeństwo dla tej aplikacji)

### Nie widzę portów /dev/ttyUSB*
- `sudo apt install usb-modeswitch`
- `lsusb` - sprawdź czy modem jest widoczny
- Spróbuj innego kabla USB
