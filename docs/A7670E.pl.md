# Ręczny test MQTT/TLS na A7670E

[English](A7670E.en.md) · [O projekcie](../README.pl.md)

Ta procedura pomaga rozdzielić problemy modemu, SIM, brokera i certyfikatu
przed uruchomieniem trackera. Zakłada płytkę SIMCom A7670E z dostępem AT przez
USB, komputer z Linuksem i istniejący listener Mosquitto TLS na porcie 8883.
Przygotuj zasilanie płytki, antenę LTE i SIM według instrukcji sprzętu.
Na czas ręcznych poleceń zamknij połączenie trackera z tym samym modemem.

Polecenia używają dokumentacyjnego adresu `203.0.113.10`; zastąp go adresem
brokera i podmień `YOUR_USER`/`YOUR_PASSWORD`. Adres używany przez klienta
musi odpowiadać certyfikatowi serwera. Użyj APN swojego operatora;
`internet` jest domyślną wartością trackera, nie ustawieniem uniwersalnym.

## Najpierw sprawdź brokera

Skopiuj certyfikat CA brokera na komputer, np.:

```bash
scp pi@192.168.2.100:/etc/mosquitto/certs/ca.crt ~/ca.crt
wc -c ~/ca.crt
```

Podmień także adres LAN. Rozmiar zależy od certyfikatu; nie musi wynosić
2195 bajtów. Uruchom subskrypcję na komputerze, używając adresu objętego
certyfikatem:

```bash
mosquitto_sub -h 203.0.113.10 -p 8883 --cafile ~/ca.crt \
  -u YOUR_USER -P YOUR_PASSWORD -t dpf/test -v
```

W drugim terminalu opublikuj wiadomość:

```bash
mosquitto_pub -h 203.0.113.10 -p 8883 --cafile ~/ca.crt \
  -u YOUR_USER -P YOUR_PASSWORD -t dpf/test -m 'hello from linux'
```

Subskrybent powinien ją wypisać. W przeciwnym razie rozwiąż błąd brokera,
certyfikatu, routingu lub zapory przed dalszymi krokami. `localhost` działa
tylko wtedy, gdy certyfikat obejmuje tę nazwę, także na hoście brokera.

## Znajdź port AT

Podłącz USB modemu i sprawdź porty:

```bash
ls /dev/ttyUSB*
dmesg | grep ttyUSB | tail -10
```

`/dev/ttyUSB2` to przykład, nie gwarantowane przypisanie. Właściwości interfejsu
USB mogą pomóc w wyborze, ale potwierdź port odpowiedzią `OK` na `AT`.
Otwieraj tylko jeden program szeregowy naraz. Przy zainstalowanym picocom:

```bash
picocom --flow n -b 115200 /dev/ttyUSB2
```

Możesz też użyć `minicom -D /dev/ttyUSB2 -b 115200` z wyłączoną sprzętową
i programową kontrolą przepływu. Wysyłaj polecenia osobno i czekaj na wyniki.
Przy wyniku asynchronicznym samo `OK` nie oznacza zakończenia operacji.

## SIM, sieć i PDP

Zbierz podstawowe informacje:

```text
AT
ATE1
AT+CMEE=2
ATI
AT+CGMR
AT+CPIN?
AT+CFUN?
AT+CSQ
AT+CPSI?
AT+CEREG?
AT+CREG?
AT+CGREG?
AT+COPS?
AT+CNMP?
AT+CNBP?
AT+CGATT?
AT+CEER
```

`CPIN: READY` oznacza gotową kartę. Jeśli pyta o PIN, podaj swój przez
`AT+CPIN="1234"` po zastąpieniu przykładu. Po odrzuceniu przerwij i wyjaśnij
stan PIN/PUK; błędna próba zużywa limit karty.

Dla LTE sprawdzaj `CEREG`: w `+CEREG: <n>,<stat>` stanem jest druga wartość.
`1` oznacza rejestrację macierzystą, `5` roaming, `2` wyszukiwanie, a `3`
odrzucenie. Wartość sygnału `99` w `CSQ` oznacza brak pomiaru. Zachowaj wynik
`CEER` przed automatycznym wyborem operatora (`AT+COPS=0`) lub skanowaniem
(`AT+COPS=?`), które może trwać długo.

Ustaw APN, aktywuj PDP i sprawdź przydzielony adres:

```text
AT+CGDCONT=1,"IP","internet"
AT+CGACT=1,1
AT+CGPADDR=1
```

Opcjonalne `AT+CPING="203.0.113.10",1,4,64,1000,10000,255` sprawdza ICMP.
Nieudany ping sam w sobie nie oznacza niedostępności TCP na porcie 8883.

## Wgraj certyfikat CA

Tracker oczekuje pliku `ca.pem` już w pamięci modemu; nie wgrywa `CR_CA_CERT`
z Credentials. Zamknij terminal szeregowy przed uruchomieniem przykładu poniżej.
Zapisz go jako `/tmp/upload_cert.py`, wskazując potwierdzony port i ścieżkę
certyfikatu.

Przykład oblicza liczbę bajtów, czeka na zachętę do wysłania danych, przesyła
niezmieniony plik i czeka na wynik końcowy. Unikaj trybów wysyłania ASCII,
które dopisują końce linii lub przekształcają bajty.

```python
from pathlib import Path
import time
import serial

port = "/dev/ttyUSB2"  # Select the verified AT port.
certificate = Path.home().joinpath("ca.crt").read_bytes()

def wait_for(ser, marker, timeout):
    deadline = time.monotonic() + timeout
    response = bytearray()
    while time.monotonic() < deadline:
        response.extend(ser.read(ser.in_waiting or 1))
        if b"ERROR" in response:
            raise RuntimeError(bytes(response))
        if marker in response:
            return bytes(response)
    raise TimeoutError(bytes(response))

with serial.Serial(port, 115200, timeout=0.2, write_timeout=10,
                   rtscts=False, xonxoff=False) as ser:
    ser.write(b"AT\r\n")
    wait_for(ser, b"\r\nOK\r\n", 5)
    command = f'AT+CCERTDOWN="ca.pem",{len(certificate)}\r\n'
    ser.write(command.encode("ascii"))
    wait_for(ser, b">", 10)
    if ser.write(certificate) != len(certificate):
        raise RuntimeError("Incomplete certificate write")
    ser.flush()
    wait_for(ser, b"\r\nOK\r\n", 30)
    ser.write(b"AT+CCERTLIST\r\n")
    print(wait_for(ser, b"\r\nOK\r\n", 5).decode(errors="replace"))
```

Uruchom go w virtualenv z pyserial:

```bash
python3 -m venv /tmp/a7670-at-venv
/tmp/a7670-at-venv/bin/pip install pyserial
/tmp/a7670-at-venv/bin/python /tmp/upload_cert.py
```

Lista musi zawierać `ca.pem`. Otwórz ponownie terminal szeregowy; przy późniejszej
diagnostyce sprawdzaj zapisane certyfikaty poleceniem `AT+CCERTLIST`.

## Połącz MQTT przez TLS

Sekwencja odpowiada obecnej konfiguracji trackera. Wysyłaj każdą linię dopiero
po zakończeniu poprzedniego polecenia:

```text
AT+CSSLCFG="sslversion",0,4
AT+CSSLCFG="authmode",0,1
AT+CSSLCFG="cacert",0,"ca.pem"
AT+CSSLCFG="ignorelocaltime",0,1
AT+CSSLCFG="enableSNI",0,0
AT+CMQTTSTART
AT+CMQTTACCQ=0,"dpf-tracker-test",1
AT+CMQTTSSLCFG=0,0
AT+CMQTTCONNECT=0,"tcp://203.0.113.10:8883",60,1,"YOUR_USER","YOUR_PASSWORD"
```

Czekaj na `+CMQTTSTART: 0`, a następnie `+CMQTTCONNECT: 0,0`. Test ma własne ID
klienta i keepalive 60 sekund; firmware używa `dpf-tracker` i 120.
Prefiks `tcp://` pozostaje także przy TLS, wybieranym konfiguracją klienta i kontekstu.

W [instrukcji SIMCom, §19.2.1](https://files.waveshare.com/wiki/A7670E-Cat-1-GNSS-HAT/A76XX_Series_AT_Command_Manual_V1.09.pdf#page=424), `sslversion=4` dopuszcza wszystkie
obsługiwane wersje, a `3` wybiera TLS 1.2. Obecne komentarze kodu nazywające
`4` TLS 1.2 nie odpowiadają tej tabeli. `authmode=1` weryfikuje certyfikat serwera;
`ignorelocaltime=1` pomija sprawdzanie jego ważności czasowej. SNI jest tu
wyłączone, tak jak w firmware. Serwer wymagający SNI potrzebuje zmiany konfiguracji.

## Opublikuj wiadomość i rozłącz

Po każdej zachęcie `>` wyślij dokładnie podaną liczbę bajtów, bez dodatkowego
CR/LF. Przykłady są w ASCII; dla innego tekstu policz bajty po zakodowaniu.

```text
AT+CMQTTTOPIC=0,8
```

Wyślij `dpf/test` (8 bajtów), po czym czekaj na `OK`.

```text
AT+CMQTTPAYLOAD=0,24
```

Wyślij `hello from A7670E modem!` (24 bajty), po czym czekaj na `OK`.

```text
AT+CMQTTPUB=0,1,60
```

Czekaj na `+CMQTTPUB: 0,0` i potwierdź u subskrybenta
`dpf/test hello from A7670E modem!`. Zamknij sesję, czekając na każdy wynik:

```text
AT+CMQTTDISC=0,60
AT+CMQTTREL=0
AT+CMQTTSTOP
```

## Diagnozuj błędy

Odczytuj `+CMQTTCONNECT: <client>,<err>` według tabeli SIMCom, nie numeracji
MQTT CONNACK. Wybrane wartości z [§18.3](https://files.waveshare.com/wiki/A7670E-Cat-1-GNSS-HAT/A76XX_Series_AT_Command_Manual_V1.09.pdf#page=417):

| Kod | Znaczenie |
| --- | --- |
| 3 / 4 / 6 | Błąd połączenia socket / utworzenia socket / odbioru wiadomości |
| 17 / 25 | Timeout / błąd DNS |
| 27 / 28 / 29 | Odrzucony protokół / ID klienta / niedostępny serwer |
| 30 / 31 | Błędne dane logowania / brak uprawnień |
| 32 / 33 | Błąd handshake / brak ustawionego certyfikatu |

Przy problemach rejestracji sprawdź SIM, antenę LTE, operatora i `CEREG`.
Przy błędach połączenia sprawdź adres PDP, routing, port nasłuchu i log brokera.
Przy certyfikatach sprawdź wgrany plik, łańcuch CA, nazwę/adres certyfikatu
oraz ustawienia TLS danej wersji modemu. Wyłączenie `authmode` usuwa uwierzytelnianie
serwera; nie uznawaj tego za udany test zweryfikowanego TLS. Sam błąd weryfikacji
nie dowodzi braku obsługi IP w SAN.

Gdy nie ma portów USB, sprawdź `lsusb`, kabel, zasilanie płytki i tryb USB.
Zapisz rewizję modemu (`CGMR`) razem z diagnostyką i korzystaj z właściwej
instrukcji. Ta procedura wymaga rzeczywistego modemu i brokera; kontrola
składni ani kompilacja firmware'u nie potwierdzają wyniku sprzętowego.
